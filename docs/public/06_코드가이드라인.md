## 1. Entity

### 1.1 핵심 결정

- `BaseEntity` 상속 — `created_at`/`updated_at`/`deleted_at` 자동 상속 + `softDelete()`/`isDeleted()` 메서드 (→ 99 §2.1)
- `@Entity`, `@Table(name = "...")` 단수형
- `@Getter` + `@NoArgsConstructor(access = AccessLevel.PROTECTED)` — setter 노출 X
- PK: `String id` UUID — Entity `create(...)` 팩토리에서 `UUID.randomUUID().toString()` 생성
- enum 필드: `@Enumerated(EnumType.STRING) + @Column(length = N)`
- 생성·수정: 정적 팩토리 + 의미 메서드 — `create(...)` / `update{Field}(...)`
- Lombok `@Data` 금지, `@ToString` 비권장 — setter 자동 생성·`equals`/`hashCode` 모든 필드 기반이라 lazy 로딩·무한 루프 위험

### 1.2 코드 예시

```java
@Entity
@Table(name = "sentence")
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class SentenceEntity extends BaseEntity {

    @Id
    @Column(name = "id", length = 36)
    private String id;

    @Column(name = "english_text", nullable = false, columnDefinition = "TEXT")
    private String englishText;

    @Enumerated(EnumType.STRING)
    @Column(name = "level", nullable = false, length = 20)
    private Level level;

    public static SentenceEntity create(String englishText, Level level) {
        SentenceEntity entity = new SentenceEntity();
        entity.id = UUID.randomUUID().toString();
        entity.englishText = englishText;
        entity.level = level;
        return entity;
    }

    public void updateLevel(Level newLevel) {
        this.level = newLevel;
    }
}
```

### 1.3 `ddl-auto = validate` 스키마 동기화

`application.properties` 의 `spring.jpa.hibernate.ddl-auto=validate` — Hibernate 가 DDL 을 만들지 않음.

신규/변경 시 동기화 대상 **3 곳**:
1. `docs/public/04_데이터모델.md` — SSOT
2. `src/main/resources/init.sql` (또는 운영 DDL)
3. `*Entity.java`

`create` / `create-drop` / `update` 사용 금지 — Entity 와 DB 가 의도 없이 어긋남.

## 2. Repository

### 2.1 핵심 결정

- `JpaRepository<E, String>` 상속
- 메서드명 명명 규칙 활용
- **모든 조회 메서드에 `AndDeletedAtIsNull` 명시** — `findById` 기본 메서드는 soft delete 무시
- 복잡 쿼리는 `@Query` (JPQL 우선, 필요 시 Native SQL)
- 반환 타입: 단건 `Optional<E>`, 다건 `List<E>` / `Page<E>`

### 2.2 코드 예시

```java
public interface SentenceRepository extends JpaRepository<SentenceEntity, String> {

    Optional<SentenceEntity> findByIdAndDeletedAtIsNull(String id);

    @Query(value = """
            SELECT * FROM sentence
            WHERE level = :level
              AND category = :category
              AND deleted_at IS NULL
            ORDER BY RANDOM()
            LIMIT 1
            """, nativeQuery = true)
    Optional<SentenceEntity> findRandomBy(@Param("level") Level level,
                                          @Param("category") Category category);
}
```

### 2.3 주의

- `findById` 기본 메서드는 soft delete 무시 — `AndDeletedAtIsNull` 명시 메서드 사용.
- enum 파라미터는 `@Enumerated(EnumType.STRING)` 컨버터가 자동 바인딩. SpEL `:#{#level.name()}` 트릭은 마지막 수단 (단순 `:level` 로 안 될 때만).
- Native SQL 은 PostgreSQL 종속 — 의식적 선택.

## 3. Service

### 3.1 핵심 결정

- `@Service` + `@RequiredArgsConstructor` + `@Slf4j`
- 메서드별 `@Transactional` (class-level X)
- 조회 전용: `@Transactional(readOnly = true)`
- import: `org.springframework.transaction.annotation.Transactional` (jakarta 아님)
- dirty checking 의식적 미사용 — 변경 후 명시 `save()`
- soft delete 는 `entity.softDelete(); repo.save(entity)` 패턴
- 도메인 예외 throw → GlobalExceptionHandler 위임

### 3.2 코드 예시 — 조회·삭제

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class SentenceService {

    private final SentenceRepository sentenceRepository;

    @Transactional(readOnly = true)
    public SentenceEntity getRandom(Level level, Category category) {
        log.info("문장 출제: level={} category={}", level, category);
        return sentenceRepository.findRandomBy(level, category)
                .orElseThrow(() -> new SentenceException.NotFound(
                        "level=" + level + ", category=" + category));
    }

    @Transactional
    public void delete(String id) {
        SentenceEntity entity = sentenceRepository.findByIdAndDeletedAtIsNull(id)
                .orElseThrow(() -> new SentenceException.NotFound(id));
        entity.softDelete();
        sentenceRepository.save(entity);
    }
}
```

### 3.3 외부 호출은 트랜잭션 밖에서

외부 HTTP 호출(예: Similarity)을 `@Transactional` 블록 안에서 부르지 말 것 — DB 커넥션이 외부 응답 대기 시간 동안 점유됨.

```java
// 안티 패턴 — 외부 호출이 트랜잭션 안
@Transactional
public AnswerResult score(...) {
    SentenceEntity sentence = sentenceRepository.findById(...);
    SimilarityScore score = similarityClient.score(...);   // ← DB 커넥션 점유 중
    ...
}

// 권장 — 트랜잭션 분리
public AnswerResult score(...) {
    SentenceEntity sentence = loadSentence(...);    // 트랜잭션 안
    SimilarityScore score = similarityClient.score(...);   // 트랜잭션 밖
    return AnswerResult.from(sentence, score);
}

@Transactional(readOnly = true)
public SentenceEntity loadSentence(String id) { ... }
```

저장이 필요한 경우 별도 빈으로 분리하는 패턴도 — `AnswerPersistenceService` 같이 DB 트랜잭션 책임만 가진 빈.

### 3.4 self-invocation 함정

같은 클래스 안의 `@Transactional` 메서드를 `this.X()` 로 호출하면 **프록시가 우회되어 트랜잭션·readOnly 가 적용되지 않음**. 분리하려면 다른 빈으로.

### 3.5 로깅 지점

| 위치 | 레벨 | 형태 |
|---|---|---|
| 주요 유스케이스 메서드 진입 | INFO | `log.info("문제 출제: level={} category={}", ...)` |
| 외부 호출 직전·직후 | INFO | `log.info("Similarity 호출"); log.info("Similarity 응답: score={}", ...)` |
| 외부 호출 실패 | ERROR | `log.error("Similarity 실패", e)` (Throwable 마지막 인자) |
| 도메인 예외 throw 직전 | (찍지 않음) | GlobalExceptionHandler 가 단일 로깅 |

## 4. Controller

### 4.1 핵심 결정

- `@RestController` + `@RequiredArgsConstructor`
- URL prefix 는 `application.properties` 의 `rest.api.version` 으로 통합 (→ 05 §4.1). 하드코딩 금지.
- 응답 항상 `ResponseEntity<T>`
- 요청 body 검증: `@Valid`
- 상태 코드 명시 — 200 / 201 + Location / 204
- 비즈니스 로직 X — Service 위임
- 예외 처리 X — GlobalExceptionHandler 위임

### 4.2 URL 버저닝

```properties
# application.properties
rest.api.version=/api/v1
```

```java
@RequestMapping("${rest.api.version}/sentences")
```

### 4.3 코드 예시 — GET

```java
@RestController
@RequestMapping("${rest.api.version}/sentences")
@RequiredArgsConstructor
public class SentenceController {

    private final SentenceService sentenceService;

    @GetMapping("/next")
    public ResponseEntity<SentenceResponse> getNext(@RequestParam Level level,
                                                    @RequestParam Category category) {
        SentenceEntity sentence = sentenceService.getRandom(level, category);
        return ResponseEntity.ok(SentenceResponse.from(sentence));
    }
}
```

### 4.4 코드 예시 — POST + 201

```java
@Value("${rest.api.version}")
private String apiPrefix;

@PostMapping
public ResponseEntity<SentenceResponse> create(@Valid @RequestBody CreateSentenceRequest request) {
    SentenceEntity sentence = sentenceService.create(request);
    return ResponseEntity
            .created(URI.create(apiPrefix + "/sentences/" + sentence.getId()))
            .body(SentenceResponse.from(sentence));
}
```

Location 헤더 URL 도 `rest.api.version` 으로 일관. 하드코딩 `/api/v1` 금지.

### 4.5 Validation 핸들러 매핑

| 예외 | 발생 시점 | 응답 코드 |
|---|---|---|
| `MethodArgumentNotValidException` | `@Valid` body 검증 실패 | 400 `TMI.COMMON.INVALID_REQUEST` |
| `MethodArgumentTypeMismatchException` | `@RequestParam` 타입 변환 실패 (enum 등) | 400 `TMI.COMMON.INVALID_REQUEST` |
| `MissingServletRequestParameterException` | 필수 파라미터 누락 | 400 `TMI.COMMON.MISSING_PARAMETER` |
| `NoResourceFoundException` | 잘못된 URL | 404 `TMI.COMMON.NOT_FOUND_URL` |
| `HttpRequestMethodNotSupportedException` | 잘못된 HTTP 메서드 | 405 `TMI.COMMON.METHOD_NOT_SUPPORTED` |

모두 GlobalExceptionHandler 가 처리 (→ 99 §2.7). Controller 에서 `try/catch` 금지.

### 4.6 헬스체크

옵션 두 가지:

| 방법 | 위치 | 장점 | 단점 |
|---|---|---|---|
| Spring Actuator `/actuator/health` | 의존성 추가만 | 표준, DB·외부 시스템 상태 자동 (HealthIndicator) | URL 이 `/actuator/health` 로 고정 |
| 직접 작성 `HealthController` | `common/controller/HealthController.java` | URL·응답 모양 자유 (`/api/v1/health` + `{status, db, similarity}`) | 직접 검사 로직 작성 |

03 §4 의 응답 형태(`{status, db, similarity}`) 가 약속된 모양이면 직접 작성 필요. Actuator 기본 응답으로 충분하면 의존성 추가가 단순.

## 5. DTO

### 5.1 핵심 결정

- `record` + 중첩 `record`
- Request 는 Bean Validation (`@NotBlank`, `@Size` 등)
- Response 는 `from(Entity)` 정적 팩토리
- 위치: 도메인 패키지의 `dto/` (request·response 통합)

### 5.2 코드 예시 — Response

```java
public record SentenceResponse(
        String sentenceId,
        String englishText,
        Level level,
        Category category
) {
    public static SentenceResponse from(SentenceEntity sentence) {
        return new SentenceResponse(
                sentence.getId(),
                sentence.getEnglishText(),
                sentence.getLevel(),
                sentence.getCategory()
        );
    }
}
```

### 5.3 코드 예시 — Request

```java
public record SubmitAnswerRequest(
        @NotBlank @Size(max = 36) String sentenceId,
        @NotBlank @Size(min = 1, max = 500) String userAnswer
) {
}
```

### 5.4 enum 검증

- 필드가 enum 타입이면 Spring 이 자동 변환 — 잘못된 값은 `MethodArgumentTypeMismatchException` → 400.
- `@Pattern` 은 `CharSequence` 만 적용. 필드가 enum 이면 `@Pattern` 사용 X (무효).
- enum 으로 받지 않고 String 으로 받아 별도 검증할 때만 `@Pattern(regexp = "DAILY|BUSINESS|TECH")`.

### 5.5 Bean Validation 메시지

- 검증 실패 시 GlobalExceptionHandler 가 `MethodArgumentNotValidException` → `TMI.COMMON.INVALID_REQUEST`.
- 필드별 메시지가 필요하면 `@NotBlank(message = "{TMI.COMMON.INVALID_REQUEST.userAnswer}")` 형태로 messages.properties 키 사용.

### 5.6 다건 응답 wrapper (Phase 5+)

다건 응답이 필요해질 시점에 공통 wrapper 도입:
```java
public record ListResponse<T>(
        List<T> items,
        String nextCursor,
        boolean hasNext,
        long totalCount
) {
    public static <T> ListResponse<T> of(List<T> items) { ... }
    public static <T> ListResponse<T> paged(List<T> items, String nextCursor, long total) { ... }
}
```
위치: `common/dto/ListResponse.java`. MVP 출제 API 는 단건이라 도입 X — Phase 5 이력 조회·검색 등이 추가되면 도입.

## 6. Exception

### 6.1 핵심 결정

- **외부 클래스 + 정적 중첩 클래스** 패턴 — `SentenceException.NotFound`, `SimilarityException.Unavailable` 등 (→ 05 §5.4)
- 외부 클래스는 인스턴스화 금지 (`private` 생성자), 케이스마다 정적 중첩 클래스가 `BaseException` 직접 상속
- ErrorType enum 은 **모듈 단일** `ETmiErrorType` — 공통·도메인 에러 모두 통합 (→ 05 §5.3)
- HttpStatus 는 enum 에 묶지 않고 **예외 생성자에서 명시**
- 위치: `{domain}/exception/{Domain}Exception.java`
- 케이스 추가 시: `ETmiErrorType` 상수 1 줄 + 정적 중첩 클래스 1 개 + messages.properties 1 줄

### 6.2 코드 예시 — `ETmiErrorType` (공통)

`common/exception/ETmiErrorType.java`
```java
@Getter
@RequiredArgsConstructor
public enum ETmiErrorType implements IErrorType {

    // 공통
    INVALID_REQUEST     ("TMI.COMMON.INVALID_REQUEST"),
    INTERNAL_ERROR      ("TMI.COMMON.INTERNAL_ERROR"),
    NOT_FOUND_URL       ("TMI.COMMON.NOT_FOUND_URL"),
    METHOD_NOT_SUPPORTED("TMI.COMMON.METHOD_NOT_SUPPORTED"),
    MISSING_PARAMETER   ("TMI.COMMON.MISSING_PARAMETER"),
    BAD_REQUEST         ("TMI.COMMON.BAD_REQUEST"),

    // Sentence
    SENTENCE_NOT_FOUND  ("TMI.SENTENCE.NOT_FOUND"),

    // Similarity
    SIMILARITY_REQUEST_INVALID("TMI.SIMILARITY.REQUEST_INVALID"),
    SIMILARITY_UNAVAILABLE    ("TMI.SIMILARITY.UNAVAILABLE"),
    ;

    private final String errorCode;
}
```

### 6.3 코드 예시 — 도메인 예외 클래스

`sentence/exception/SentenceException.java`
```java
public class SentenceException {

    private SentenceException() {}

    /** 조건에 맞는 영어 문장이 없음 */
    public static class NotFound extends BaseException {
        public NotFound(String detail) {
            super(HttpStatus.NOT_FOUND, ETmiErrorType.SENTENCE_NOT_FOUND, detail);
        }
    }
}
```

새 케이스 추가 (예: `Duplicate`):
```java
public static class Duplicate extends BaseException {
    public Duplicate(String englishText) {
        super(HttpStatus.CONFLICT, ETmiErrorType.SENTENCE_DUPLICATE, englishText);
    }
}
```

### 6.4 호출

```java
throw new SentenceException.NotFound(sentenceId);
```

### 6.5 외부 시스템 예외

같은 패턴을 `infra/` 외부 시스템 예외에도 적용 — `SimilarityException.RequestInvalid`, `SimilarityException.Unavailable` 등 (→ 05 §5.7).

### 6.6 주의

- 외부 클래스 인스턴스화 금지 — `private` 생성자.
- 예외 throw 직전에 로그 찍지 말 것 — GlobalExceptionHandler 가 단일 로깅 (§3.5).
- 도메인 예외 추가 시 GlobalExceptionHandler 코드 변경 불요 — `BaseException` 단일 핸들러로 흡수.

## 7. Test

### 7.1 Phase 별 적용 범위

| Phase | 적용 |
|---|---|
| 4 (Sentence) | `@SpringBootTest` 통합 테스트 1~2 개 |
| 5 (Similarity 도입 후) | WireMock 추가 (외부 호출 mock) |
| 6 | 단위 테스트 + 회귀 테스트 정비 |

### 7.2 통합 테스트 — 핵심 결정

- 골격: `@SpringBootTest + @AutoConfigureMockMvc + @ActiveProfiles("test") + @Transactional`
- 메서드명 `shouldXxx_whenYyy`, `@DisplayName` 한국어
- 시나리오 그룹화: `@Nested + @DisplayName` 2 단 구조
- DB: PostgreSQL 종속 기능(Native `RANDOM()`, jsonb)이 있어 **Testcontainers 권장** (H2 비추천)

### 7.3 통합 테스트 코드 예시

```java
@SpringBootTest
@AutoConfigureMockMvc
@ActiveProfiles("test")
@Transactional
class SentenceControllerIntegrationTest {

    @Autowired private MockMvc mockMvc;
    @Autowired private SentenceRepository sentenceRepository;

    @Nested
    @DisplayName("GET /api/v1/sentences/random")
    class GetNext {

        @Test
        @DisplayName("조건에 맞는 문장이 있으면 200")
        void shouldReturnSentence_whenMatchFound() throws Exception {
            // given
            sentenceRepository.save(SentenceEntity.create("Sounds good.", Level.LEVEL_1));

            // when / then
            mockMvc.perform(get("/api/v1/sentences/random")
                            .param("level", "LEVEL_1")
                            .param("category", "DAILY"))
                    .andExpect(status().isOk())
                    .andExpect(jsonPath("$.englishText").value("Sounds good."));
        }

        @Test
        @DisplayName("조건에 맞는 문장이 없으면 404")
        void shouldReturn404_whenNotFound() throws Exception {
            mockMvc.perform(get("/api/v1/sentences/random")
                            .param("level", "LEVEL_5")
                            .param("category", "TECH"))
                    .andExpect(status().isNotFound())
                    .andExpect(jsonPath("$.error.code").value("TMI.SENTENCE.NOT_FOUND"));
        }
    }
}
```

### 7.4 단위 테스트 — BDD Mockito

복잡한 분기·예외 처리는 Service 단위 테스트로 분리.

```java
@ExtendWith(MockitoExtension.class)
class SentenceServiceTest {

    @Mock SentenceRepository sentenceRepository;
    @InjectMocks SentenceService sentenceService;

    @Test
    @DisplayName("조건에 맞는 문장이 없으면 SentenceException.NotFound")
    void shouldThrowNotFound_whenRepositoryEmpty() {
        // given
        given(sentenceRepository.findRandomBy(Level.LEVEL_3, Category.DAILY))
                .willReturn(Optional.empty());

        // when / then
        assertThatThrownBy(() -> sentenceService.getRandom(Level.LEVEL_3, Category.DAILY))
                .isInstanceOf(SentenceException.NotFound.class);

        then(sentenceRepository).should().findRandomBy(Level.LEVEL_3, Category.DAILY);
    }
}
```

- `given/willReturn/then.should()` BDD 스타일.
- `@InjectMocks` 로 의존성 자동 주입.
- 통합 테스트보다 빠름 — 분기·예외 경계 검증에 사용.

### 7.5 주의

- `@Transactional` 테스트 롤백은 같은 트랜잭션 안에서만 — `@Async` / `Propagation.REQUIRES_NEW` 결합 시 안 됨.
- MockMvc 는 서블릿 컨테이너를 띄우지 않음. 필터·CORS 검증이 필요하면 `TestRestTemplate + @SpringBootTest(webEnvironment = RANDOM_PORT)`.
- 단위 테스트는 빠른 피드백·분기 검증, 통합 테스트는 실제 시나리오 — 둘 다 적정 비율로.

## 8. Swagger (SpringDoc OpenAPI)

### 8.1 라이브러리

- **SpringDoc OpenAPI** — `springdoc-openapi-starter-webmvc-ui`. Springfox 는 유지보수 중단, 사용 X.

### 8.2 어노테이션 위치 원칙

**Controller 는 로직만, 문서화 어노테이션은 API 인터페이스로 분리.**

| 어노테이션 | 위치 | 필수 |
|---|---|---|
| `@Tag(name, description)` | **`{Domain}Api` 인터페이스** | ✓ |
| `@Operation(summary, description)` | **인터페이스 메서드** | ✓ |
| `@ApiResponses({ @ApiResponse(...) })` — 200 + 도메인 에러 | **인터페이스 메서드** | ✓ |
| `@Parameter(description, example)` — `@RequestParam` · `@PathVariable` | **인터페이스 메서드 파라미터** | ✓ |
| `@Schema(description, example)` — Request/Response DTO 필드 | **DTO 필드** | ✓ |
| `@RestController`, `@RequestMapping`, HTTP 메서드 매핑 | **Controller 구현체** | ✓ |

→ Controller 코드는 짧고 로직 중심, 인터페이스는 명세 중심 — **관심사 분리**.

Bean Validation (`@NotBlank`/`@Size` 등) 은 Swagger 가 자동 스키마화 — 별 어노테이션 불요.

### 8.3 API 인터페이스 예시

**위치**: `com.tmi.core.{domain}.controller.{Domain}Api`

```java
@Tag(name = "Sentence", description = "영어 문장 출제")
public interface SentenceApi {

    @Operation(
        summary = "랜덤 문장 출제",
        description = """
                난이도·카테고리 조건에 맞는 문장 1건을 무작위 반환.
                모범 답안(koreanRef)은 응답에 포함되지 않음 (정답 노출 방지).
                """
    )
    @ApiResponses({
        @ApiResponse(
            responseCode = "200", description = "출제 성공",
            content = @Content(
                schema = @Schema(implementation = SentenceResponse.class),
                examples = @ExampleObject(name = "success", value = """
                        {
                          "sentenceId": "01HTM3ABCXYZ",
                          "englishText": "I had a rough day at work today.",
                          "level": "LEVEL_3",
                          "category": "DAILY"
                        }
                        """)
            )
        ),
        @ApiResponse(
            responseCode = "400", description = "level·category 누락·잘못된 값",
            content = @Content(
                schema = @Schema(implementation = ErrorResponse.class),
                examples = @ExampleObject(name = "invalid-level", value = """
                        {
                          "error": {
                            "code": "TMI.COMMON.INVALID_REQUEST",
                            "message": "level: must be one of LEVEL_1 ~ LEVEL_5"
                          }
                        }
                        """)
            )
        ),
        @ApiResponse(
            responseCode = "404", description = "조건에 맞는 문장 없음",
            content = @Content(
                schema = @Schema(implementation = ErrorResponse.class),
                examples = @ExampleObject(name = "not-found", value = """
                        {
                          "error": {
                            "code": "TMI.SENTENCE.NOT_FOUND",
                            "message": "level=LEVEL_5, category=TECH"
                          }
                        }
                        """)
            )
        )
    })
    ResponseEntity<SentenceResponse> getRandom(
            @Parameter(description = "난이도", example = "LEVEL_3", required = true) Level level,
            @Parameter(description = "카테고리", example = "DAILY", required = true) Category category);
}
```

### 8.4 Controller 구현체 예시

**위치**: `com.tmi.core.{domain}.controller.{Domain}Controller`

```java
@RestController
@RequestMapping("${rest.api.version}/sentences")
@RequiredArgsConstructor
public class SentenceController implements SentenceApi {

    private final SentenceService sentenceService;

    @Override
    @GetMapping("/random")
    public ResponseEntity<SentenceResponse> getRandom(@RequestParam Level level,
                                                       @RequestParam Category category) {
        SentenceEntity sentence = sentenceService.getRandom(level, category);
        return ResponseEntity.ok(SentenceResponse.from(sentence));
    }
}
```

→ Controller 는 매핑 어노테이션 + 로직만. 문서 어노테이션은 상속으로 승계.

### 8.5 DTO 예시

**Response**
```java
public record SentenceResponse(
        @Schema(description = "문장 ID (UUID)", example = "01HTM3ABCXYZ")
        String sentenceId,

        @Schema(description = "영어 문장 (사용자가 번역할 원문)", example = "I had a rough day at work today.")
        String englishText,

                allowableValues = {"LEVEL_1", "LEVEL_2", "LEVEL_3", "LEVEL_4", "LEVEL_5"})

                allowableValues = {"DAILY", "BUSINESS", "TECH"})
        Category category
) {
    public static SentenceResponse from(SentenceEntity sentence) { ... }
}
```

**Request**
```java
public record SubmitAnswerRequest(
        @Schema(description = "출제받은 문장 ID (36자 UUID)", example = "01HTM3ABCXYZ", requiredMode = REQUIRED)
        @NotBlank @Size(max = 36)
        String sentenceId,

        @Schema(description = "사용자가 입력한 한국어 번역 (1~500자)",
                example = "오늘 회사에서 힘든 하루였다",
                requiredMode = REQUIRED,
                minLength = 1, maxLength = 500)
        @NotBlank @Size(min = 1, max = 500)
        String userAnswer
) { }
```

- `allowableValues` — enum 필드의 허용값을 Swagger UI 에 명시.
- `requiredMode = REQUIRED` — 필수 필드 표시 (Bean Validation 이 자동 처리 못 하는 케이스 명시).

### 8.6 응답·요청 예시 상세화 정책

응답 코드마다 **최소 1 개의 `@ExampleObject`** 를 두어 실제 JSON body 를 보임.

- 성공 응답: `name = "success"` — 대표 케이스
- 에러 응답: 에러 코드마다 별 `@ExampleObject` (`name = "not-found"`, `name = "invalid-request"` 등)
- 시나리오가 여러 개면 `examples = { @ExampleObject(...), @ExampleObject(...) }` 배열로

예시 body 는 03 API 명세의 응답과 형식 일치 — 명세와 코드가 어긋나지 않도록.

### 8.7 에러 응답 스키마 정책

모든 도메인 에러는 `ErrorResponse` (99 §2.8) 로 반환. 인터페이스의 `@ApiResponse` 에 `schema = @Schema(implementation = ErrorResponse.class)` + `examples` 명시.

**공통 에러 (400 · 500) 는 매 엔드포인트에 안 적어도 OK** — 명세에 중복. **도메인 특화 에러** (404 SENTENCE_NOT_FOUND, 502 SIMILARITY_REQUEST_INVALID, 503 SIMILARITY_UNAVAILABLE 등) 는 반드시 명시.

### 8.8 접근 URL

| URL | 용도 |
|---|---|
| `/swagger-ui.html` | Swagger UI (사람용 문서·테스트) |
| `/v3/api-docs` | OpenAPI JSON 스펙 (기계용) |

`application.properties` 에서 경로 커스터마이징 가능 (필요 시).

### 8.9 그룹핑 (선택)

도메인이 늘어나면 `GroupedOpenApi` 빈으로 `/v3/api-docs/sentence`, `/v3/api-docs/answer` 분리 가능. MVP 는 단일 그룹.

### 8.10 주의

- `@Operation` 의 `summary` 는 짧게 (Swagger UI 목록에 표시). `description` 이 자세한 설명.
- `@ExampleObject.value` 는 03 API 명세의 응답 body 와 형식 일치 (양쪽 문서·코드 어긋나지 않게).
- `@Schema.example` 은 개별 필드용, `@ExampleObject` 는 전체 body 용 — 둘 다 사용.
- 이력 저장 도입으로 `POST /answers` 가 `201` 로 바뀌면 `@ApiResponse(responseCode = "201", ...)` 로 갱신.
- 인터페이스는 순수 문서용 — default method 사용 X, 실제 로직은 Controller 구현체가 담당.
