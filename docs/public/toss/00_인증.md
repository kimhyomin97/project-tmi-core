# 00. 인증 설계

토스증권 Open API 는 OAuth 2.0 Client Credentials Grant.
모든 API (`POST /oauth2/token` 제외) 는 `Authorization: Bearer {access_token}` 필수.

---

## 1. 자격증명 2 계층

| 자격증명 | 사용처 | 헤더 |
|---|---|---|
| `client_id` + `client_secret` | `POST /oauth2/token` **한 곳** | `Basic base64(id:secret)` |
| `access_token` | 그 외 모든 API | `Bearer {token}` |

`client_secret` 은 토큰 발급용 마스터 키. API 호출에는 실지 않음.

---

## 2. 발급 흐름

`POST /oauth2/token` (Basic Auth + `grant_type=client_credentials`)
→ `{ access_token, token_type, expires_in }` 응답 (OAuth 2.0 표준)
→ 이후 API 요청 헤더에 `Authorization: Bearer {access_token}`

Grant = `client_credentials` (사용자 로그인 없는 M2M).

---

## 3. 캐싱

`TossTokenProvider` 가 in-memory 로 캐시. 만료 60 초 전(`REFRESH_MARGIN`)까지 재사용, 임박 시 `TossAuthClient.fetchToken()` 재소환. `synchronized` 로 동시 발급 방지.

---

## 4. 코드 분리 원칙

- `TossAuthClient` — 유일하게 `client_secret` 접근 (Basic Auth 조립 지점)
- `TossTokenProvider` — 캐시 브릿지
- 도메인 클라이언트 (`TossHoldingsClient` 등) — `Bearer` 만 수신

secret 노출 표면을 코드 1 지점으로 국지화 → 회전·감사·테스트 격리.

---

## 5. 보안

- `client_secret` 리포지토리 커밋 금지 — 환경 변수 `TOSS_CLIENT_ID` / `TOSS_CLIENT_SECRET` 주입
- `access_token` 값은 로그 미출력 (재발급 이벤트만 기록)
