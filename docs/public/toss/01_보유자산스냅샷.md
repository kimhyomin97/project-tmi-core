# 01. 보유 자산 스냅샷

Toss 증권 Open API `/holdings` 응답을 시간당 1회 폴링해 DB에 시계열로 축적. 목적 = 일간 손익·일일 총 금액 지표화, 시점 간 비교.

---

## 1. 스코프

- **대상 데이터**: 계좌 단위 `HoldingsOverview` 요약 (투자원금·시장 평가·손익·일간 손익·율)
- **원본 보존**: `items[]` 포함 전체 응답을 `raw_response` JSONB 로 백업 (종목별 분석은 향후 파생 뷰/ETL 로 처리)
- **비대상**: 실주문·조건부주문 실행, 실시간 시세 폴링, 대시보드 UI (후속 phase)

---

## 2. 스케줄

- **주기**: 매 정각 (1 시간, cron `0 0 * * * *`)
- **타임존**: `Asia/Seoul` (KST)
- **장 개폐 필터**: 없음 — 매 정각 그대로 호출. 장외 시간대는 직전 종가 반영된 값이 기록됨 (분석 시 시간 필터로 구분).
- **동시성**: 계좌 여러 개일 경우 순차 호출 (Rate Limit 관리)

---

## 3. 시퀀스

```
Scheduler(hourly, KST 정각)
     │
     ▼
HoldingsSnapshotService.collect()
     │
     ├─ (1) TossTokenProvider.getAccessToken()   ← 상세: 00_인증.md
     │
     ├─ (2) accountSeq ← toss.default-account-seq (프로퍼티 하드코딩)
     │
     └─ (3) TossHoldingsClient.get(bearer, accountSeq)   ← GET /holdings
                 │
                 ▼
            HoldingsSnapshotRepository.save(...) → UNIQUE (account_seq, snapshot_at)
```

**트랜잭션 경계**: `save` 호출만 트랜잭션. 외부 API 호출은 트랜잭션 밖.

**인증**: OAuth 2.0 Client Credentials + Bearer 토큰 캐싱. 자격증명 2 계층 / 발급·캐싱 정책은 [`00_인증.md`](00_인증.md) 참조.

**계좌 선택**: MVP 는 프로퍼티 단일 계좌. `/accounts` 는 부팅·curl 로 seq 확인 후 프로퍼티에 주입 (스케줄러 경로 미사용).

## 4. 스키마

### 테이블: `toss_holdings_snapshot`

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | bigserial | PK | 스냅샷 식별자 |
| `account_seq` | bigint | NOT NULL | Toss 계좌 식별키 |
| `snapshot_at` | timestamptz | NOT NULL | 정각 시각 (KST) |
| `snapshot_date` | date | NOT NULL | KST 기준 날짜 (일간 집계 인덱스) |
| `total_purchase_krw` | numeric(20,4) | NOT NULL | 투자원금 (KRW) |
| `total_purchase_usd` | numeric(20,4) | NULL 허용 | 투자원금 (USD) — 해외 미보유 시 null |
| `market_value_krw` | numeric(20,4) | NOT NULL | 시장 평가금액 (KRW) |
| `market_value_usd` | numeric(20,4) | NULL 허용 | 시장 평가금액 (USD) |
| `profit_loss_krw` | numeric(20,4) | NOT NULL | 총 손익금액 (KRW) |
| `profit_loss_usd` | numeric(20,4) | NULL 허용 | 총 손익금액 (USD) |
| `daily_pl_krw` | numeric(20,4) | NOT NULL | 일간 손익금액 (KRW) |
| `daily_pl_usd` | numeric(20,4) | NULL 허용 | 일간 손익금액 (USD) |
| `profit_loss_rate` | numeric(9,6) | NOT NULL | 총 손익률 (원화 환산 후 통합, 0.1516 = 15.16%) |
| `daily_pl_rate` | numeric(9,6) | NOT NULL | 일간 손익률 (원화 환산 후 통합) |
| `raw_response` | jsonb | NOT NULL | `/holdings` 응답 원본 (items[] 포함) |
| `created_at` | timestamptz | DEFAULT now() | 레코드 생성 시각 |

**제약**:
- `UNIQUE (account_seq, snapshot_at)` — 재실행/중복 삽입 방지
- `INDEX (snapshot_date, account_seq)` — 일간 집계 조회 최적화

**설계 근거**:
- Toss `Price` 스키마가 KRW 필수·USD 옵셔널이므로 컬럼도 동일한 nullable 정책
- 율은 원화 환산 통합값 단일 스칼라 → 단일 컬럼
- `raw_response` 원본 보존 → 종목별·통화 추가·필드 확장 시 재분석 가능

## 5. 환경 변수 / 설정

`application.properties`

```properties
# Toss Open API
toss.base-url=https://openapi.tossinvest.com
toss.client-id=${TOSS_CLIENT_ID}
toss.client-secret=${TOSS_CLIENT_SECRET}
toss.timeout-ms=3000

# 대상 계좌 (MVP: 1개 고정)
toss.default-account-seq=${TOSS_DEFAULT_ACCOUNT_SEQ}

# Scheduler
toss.holdings.schedule-cron=0 0 * * * *
toss.holdings.timezone=Asia/Seoul
```

**민감 정보**: `client-id` / `client-secret` 은 환경 변수 주입, 리포지토리 커밋 금지.

## 6. 에러 정책

| 상황 | HTTP | 처리 |
|---|---|---|
| `/oauth2/token` 4xx (인증 실패) | 401/400 | 로그 ERROR, 스냅샷 skip, 알림 확장 여지 |
| `/oauth2/token` 5xx / 네트워크 | 5xx / IOException | 재시도 1 회, 실패 시 skip |
| `/holdings` 4xx (권한·형식) | 4xx | 로그 WARN, 스냅샷 skip |
| `/holdings` 5xx / 타임아웃 | 5xx | 재시도 1 회, 실패 시 skip |
| DB `UNIQUE` 위반 | — | 중복 스냅샷 시각 → 로그 INFO, 무시 |

**중요**: 스케줄러 예외로 종료 금지. 모든 실패는 catch 후 다음 tick 진행.

## 7. 후속 phase (문서 대상 아님)

- **02. 일간 집계 뷰**: `snapshot_date` 기준 `MAX(snapshot_at)` 종가 스냅샷 파생 뷰
- **03. 지표 대시보드 API**: 일별/시간별 손익·평가금액 시계열 조회
- **04. 종목별 시계열**: `raw_response -> 'items'` 파싱 → `toss_holding_item_snapshot` 정규화 (필요 시)
- **05. 다중 계좌 지원**: `toss.default-account-seq` 프로퍼티 제거, `/accounts` 폴링 기반 자동 감지 + 계좌별 스냅샷 병렬화
