# 응답·문서 정리 (clean)

> 매번 "짧게 다시 써줘" / "표 빼고" / "문체 바꿔" 를 반복하지 않고 **한 번에** 재가공.

**내용은 보존, 형식만 변경**. verify-claim 이 사전 검증이라면 이 스킬은 사후 재포맷.

## 호출

```
/clean                              → 직전 응답, L2 (기본)
/clean L1                           → 직전 응답, 가볍게
/clean L3                           → 직전 응답, 공격적
/clean docs/public/01_기획.md        → 파일, L2
/clean docs/public/01_기획.md L3     → 파일, 공격적
```

## 레벨

| 레벨 | 처리 | 분량 감축 |
|---|---|---|
| **L1** | 상투어·빈말·명백한 중복 제거. 구조 유지 | ~15% |
| **L2** (기본) | L1 + 1-2줄 표 문장화, 불필요 섹션 평평화, 종결어미 → 명사구 | 30-50% |
| **L3** | L2 + 비핵심 서두·요약·메타 삭제, 수식어 최소화 | 60%+ |

## 제거 대상 (레벨 누적)

### L1 — 가벼운 손질

- **상투어 서두**: "물론입니다", "좋은 질문입니다", "도와드리겠습니다"
- **중복 재진술**: "요약하면", "결론적으로", "다시 말해" 로 시작하는 반복 도입부
- **과한 이모지·구분선**: 의미 없는 🎉 / 🚀 / `---` 연발
- **불필요한 강조**: 모든 bullet 이 **bold** 인 경우

### L2 — 적정 손질 (L1 포함)

- **표 과잉**: 1-2 줄 표를 문장으로 (표는 **비교·대조·매핑 3항목 이상** 일 때만)
- **섹션 과잉**: 1-2 문단짜리 `###` 헤더 제거 후 평평하게
- **종결어미**: "~입니다" / "~했습니다" / "~합니다" → 명사구
- **중복 bullet**: 같은 메시지를 여러 bullet 로 쪼갠 것 통합
- **군더더기 접속어**: "그리고", "또한", "추가로" 반복

### L3 — 공격적 (L2 포함)

- **메타 설명**: "이 응답은 ~ 를 다룹니다" 같은 자기언급
- **선택지 블록**: 결정 질의가 아닐 때의 `(1) (2) (3)`
- **완충 표현**: "~ 할 수도 있습니다", "~ 한 편입니다"
- **수식어**: "매우", "상당히", "꽤" 류 삭제
- **중간 요약**: 섹션 끝마다 붙는 "→ 즉" 재진술

## 보존 (강도 무관)

- 사실·결정·근거
- 코드 블록·명령·경로
- 외부 계약 (API 명세, 에러 코드, DB 스키마 조항)
- 사용자가 지정한 강조·주의 문구
- 선택지 블록 — **결정 질의일 때는** 유지

## 금지

- 사실 변경·수정
- 결론·결정 바꾸기
- 근거·출처 삭제
- 코드 내용 축약·생략 (주석 단순화는 예외)
- 사용자 지시된 섹션·항목 삭제

## 예시

### Before (L2 대상)

```markdown
## 결과 요약

변경 사항은 다음과 같습니다:

| 항목 | 값 |
| --- | --- |
| 커밋 | abc123 |

- 커밋이 성공적으로 생성되었습니다
- 푸시도 정상적으로 완료되었습니다

요약하면, 커밋과 푸시 모두 성공했습니다. 🎉
```

### After (L2)

```markdown
커밋 `abc123` 생성, 푸시 완료.
```

### Before (L2 대상, 설명형)

```markdown
## 개요

이 문서는 OAuth 2.0 Client Credentials 인증 방식에 대해 설명합니다.

### 1. 인증 방식 소개

OAuth 2.0 은 널리 사용되는 표준 인증 프로토콜입니다.
Client Credentials 는 그 중에서도 M2M 통신에 특화된 방식입니다.
사용자 로그인이 필요 없기 때문에 서버 간 통신에 적합합니다.

### 2. 발급 흐름

토큰 발급은 다음과 같이 진행됩니다.

- client_id 와 client_secret 을 준비합니다
- POST /oauth2/token 을 호출합니다
- 응답으로 access_token 을 받습니다
```

### After (L2)

```markdown
OAuth 2.0 Client Credentials — M2M 통신용. 사용자 로그인 없이 서버 간 토큰 발급.

## 발급 흐름

`POST /oauth2/token` (client_id + client_secret) → `access_token`
```

## 자가점검

- [ ] 삭제한 것 중 사실·결정·근거 없음
- [ ] 코드 블록·경로 그대로
- [ ] 레벨 가이드 지킴 (L1/L2/L3)
- [ ] 명사구, 종결어미 없음 (L2+)
- [ ] 표는 3항목 이상 비교·매핑일 때만 (L2+)

## 다른 스킬과의 관계

- **`commit-message`**: 커밋 subject 쓸 때 자동으로 유사 효과. 별개 체계
- **`verify-claim`**: 사전 검증 (증거 요구). clean 은 사후 재포맷. 상호보완
- **`feedback_guide_brevity` (MEMORY)**: 코드 작업 안내 brevity — 이 스킬이 전범위로 확장
